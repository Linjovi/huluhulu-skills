# DCF模型 -- 故障排查

当DCF模型输出异常时，按以下步骤诊断和修复。

---

## 问题1：模型返回错误值

### 症状

- 内含股价为负数、极大值或明显不合理的数值
- 估值汇总中的某些行出现负值（如终值为负、PV为负）
- 敏感性表中出现N/A或异常值

### 诊断步骤

**第1步：检查终值增长率与WACC的关系**

终值 = 终值FCF / (WACC - 终值增长率)

- 如果终值增长率 >= WACC -> 分母为零或负 -> 终值为无限或负值
- 修复：确保终值增长率 < WACC，通常低2-5个百分点以上

**第2步：检查FCF是否持续为负**

- 如果预测期所有年份FCF都为负 -> PV之和为负 -> 可能导致企业价值为负
- 检查NOPAT是否为正（EBIT * (1-税率)）
- 检查CapEx是否远大于NOPAT + D&A

**第3步：检查折现因子是否计算正确**

折现因子 = 1 / (1 + WACC)^期间

- 期间应使用年中惯例：0.5, 1.5, 2.5...
- 如果期间使用整数（1, 2, 3...），折现会过度，估值偏低
- 检查WACC是否为合理值（7-15%范围）

**第4步：检查公式引用是否正确**

逐行检查关键公式：
- EBIT是否正确引用了毛利润和运营费用
- NOPAT是否正确引用了EBIT和税费
- FCF是否正确引用了NOPAT、D&A、CapEx和delta_NWC
- PV是否正确引用了FCF和折现因子

## 问题2：估值不合理

### 症状

- 内含股价与当前股价差距过大（如内含价格是当前价格的5倍或0.2倍）
- 终值占EV比例超过80%
- 关键倍数（EV/EBITDA、P/E）与同行差异过大

### 诊断步骤

**第1步：检查终值占EV比例**

| 终值占EV比例 | 判断 |
|-------------|------|
| 50-70% | 正常范围 |
| 70-75% | 偏高，需要审视终值假设 |
| > 75% | 异常，模型过度依赖终值 |

终值占比过高意味着：
- 预测期的FCF贡献太小 -> 可能增长率假设过低或利润率假设过低
- 终值假设过于乐观 -> 可能终值增长率过高
- WACC过低 -> 终值被过度折现不足

修复方向：
- 提高预测期增长率或利润率
- 降低终值增长率
- 提高WACC

**第2步：检查WACC是否合理**

对照同行和行业：
- 大盘稳定公司WACC 7-9%
- 成长型公司WACC 9-12%
- 高增长/高风险公司WACC 12-15%

如果WACC明显偏离行业水平：
- 检查Beta是否正确（应使用杠杆Beta，而非原始Beta）
- 检查无风险利率是否使用当前10年期国债收益率
- 检查股权风险溢价是否在4.5-6.5%范围

**第3步：检查增长率假设是否合理**

- 预测期增长率是否远高于行业长期增长率
- 终值增长率是否远高于GDP增长率
- 增长率轨迹是否平滑回落

| 增长率异常 | 可能原因 |
|-----------|---------|
| 增长率始终很高 | 未体现增长放缓趋势 |
| 增长率突然跳跃 | 未平滑过渡 |
| 终值增长率过高 | 超过了长期GDP增长 |

**第4步：与可比公司交叉验证**

将DCF得出的关键倍数与可比公司对比：

| 倍数 | DCF推导值 | 同行范围 | 判断 |
|------|-----------|---------|------|
| EV/EBITDA | ? | ? | 是否在同行范围内 |
| P/E | ? | ? | 是否在同行范围内 |
| EV/Revenue | ? | ? | 是否在同行范围内 |

如果DCF推导倍数远超同行：
- 可能增长率假设过于乐观
- 可能WACC过低
- 可能利润率假设过高

**第5步：检查净债务处理**

- 确认净债务 = 总债务 - 现金及等价物（不是总债务 + 现金）
- 确认从EV中减去净债务（不是加上）
- 确认使用稀释股数（不是基本股数）

## 问题3：情景选择器不工作

### 症状

- 切换情景选择器（1/2/3）后，模型输出不变
- 某些行正确响应情景切换，但其他行不变
- 情景选择器指向Base但模型使用Bear的假设值

### 诊断步骤

**第1步：检查整合列是否正确使用INDEX公式**

整合列的每个假设行必须使用INDEX从情景区块取值：
```
正确: INDEX(Bear假设:Base假设:Bull假设, 选择器值)
错误: 直接引用某个情景区块的固定单元格
错误: 使用嵌套IF（容易引用错误）
```

**第2步：检查主预测列是否引用整合列**

主预测列（收入、EBIT等）必须引用整合列的值：
```
正确: 收入FY1 = 上年收入 * (1 + 整合列增长率)
错误: 收入FY1 = 上年收入 * (1 + Base增长率)  -- 不响应情景切换
```

**第3步：检查情景选择器值是否正确传递**

- 选择器值应为1、2或3（整数）
- 如果选择器引用了错误单元格 -> 模型可能始终使用同一情景
- 确认选择器单元格在模型中只出现一次，避免冲突

**第4步：检查WACC和终值增长率是否按情景变化**

在三种情景中：
- Bear: 较高WACC + 较低终值增长率
- Base: 中等WACC + 中等终值增长率
- Bull: 较低WACC + 较高终值增长率

如果WACC和终值增长率不随情景变化，即使收入和EBIT正确切换，估值仍会偏向单一情景。

### 修复流程

1. 逐一检查整合列的每个行 -- 确认都使用INDEX公式
2. 逐一检查主预测列的每个行 -- 确认都引用整合列
3. 修改任何直接引用固定情景的公式
4. 修改任何使用嵌套IF的公式 -> 替换为INDEX
5. 确认WACC和终值增长率也通过情景选择器切换
6. 验证：切换选择器从1到2到3，检查每个关键输出是否变化

## 问题4：敏感性分析不正确

### 症状

- 中心单元格值不等于模型实际内含股价
- 敏感性表中出现负值或不合理的极大值
- 估值变化方向不正确（如WACC升高时估值也升高）

### 诊断步骤

**第1步：验证中心单元格**

中心单元格 = 基准WACC与基准终值增长率的交叉
其值必须精确等于模型实际内含股价

如果不等：
- 敏感性表的DCF重算逻辑与主模型不一致
- 可能是折现期间计算不同（整数vs年中）
- 可能是终值FCF计算方式不同

**第2步：检查变化方向**

| 参数变化 | 对估值的正确影响 |
|---------|---------------|
| WACC升高 | 内含股价下降 |
| 终值增长率升高 | 内含股价上升 |
| 收入增长率升高 | 内含股价上升 |
| EBIT利润率升高 | 内含股价上升 |
| Beta升高 | 内含股价下降（通过推高WACC） |
| 无风险利率升高 | 内含股价下降 |

如果方向反了：
- 可能是公式符号错误
- 可能是折现因子计算错误

**第3步：检查边界条件**

- 确认所有终值增长率组合 < WACC
- 确认没有产生无限值的单元格
- 确认WACC最低行的估值最高（方向正确）

**第4步：检查是否使用了完整DCF重算而非近似**

- 每个单元格必须是完整重算：收入 -> EBIT -> FCF -> PV -> 终值 -> EV -> 股权价值 -> 每股价格
- 不应使用线性插值或简化公式
- 不应只重算终值而跳过FCF重算
