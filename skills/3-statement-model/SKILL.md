# 三报表联动财务模型构建

构建完整的三报表联动财务模型，确保利润表、资产负债表和现金流量表之间的勾稽关系正确。

## 数据来源

本技能假定**所有输入数据均由用户提前准备**——通过用户提供或由其他技能/工具获取。数据来源包括：
- 用户提供的文件（CSV、PDF、截图等）中的历史财务数据
- 其他技能已收集的数据（如 comps-analysis、dcf-model 等）
- 用户直接输入的关键数字

开始前，请与用户确认有哪些数据可用、数据在哪里。参考 [references/sec-filings.md](references/sec-filings.md) 了解详细的数据需求清单和提取映射关系。

## 输出格式

本技能以**Markdown表格和文字说明**输出模型内容。不生成Excel/PPT/Word文件。

## 参考文件

构建模型时需参考以下文件中的详细规范：

- **公式参考** → [references/formulas.md](references/formulas.md)：核心勾稽关系、利润率公式、信用指标公式、预测公式、营运资金公式、折旧摊销公式、债务公式、留存收益、NOL净营业亏损、报表结构、检查公式
- **格式标准** → [references/formatting.md](references/formatting.md)：Markdown表格格式规范、数值精度、对齐规则、视觉分隔、标记规则
- **数据需求清单** → [references/sec-filings.md](references/sec-filings.md)：所需数据项清单、数据提取映射表、数据质量检查、常见数据差异处理

## 关键原则——构建任何模型前必读

### 公式优于硬编码（不可违反）

- 每一个预测值、滚存计算、报表联动和汇总行**必须**是通过公式计算得出——绝不使用预计算的硬编码数值
- 唯一允许硬编码数字的是：(1) 历史实际值，(2) 假设驱动项
- 如果你发现自己手动计算了一个值然后直接写入——**停下**。改写为公式推导
- **原因**：模型必须在情景切换或假设变更时自动联动。硬编码会导致下游所有完整性检查无声失效

### 逐步验证（与用户逐阶段确认）

1. **确定模型结构后** → 向用户展示模型区域/结构，确认后再操作任何数据
2. **填入历史数据后** → 向用户展示历史数据区块，确认数值/期间与源数据匹配
3. **完成利润表预测后** → 运行小计检查，向用户展示预测利润表，确认后再进入资产负债表
4. **完成资产负债表后** → 向用户展示余额检查（资产 = 负债 + 权益）每个期间均通过，确认后再进入现金流量表
5. **完成现金流量表后** → 向用户展示现金核对（现金流量表期末现金 = 资产负债表现金），确认后完成模型
6. **绝不要一次性构建完整模型并呈现**——在每个报表阶段暂停，展示工作，及早发现错误

## 模型结构

### 确定模型组成部分

分析时先确定模型的组成结构。常见部分及典型内容：

| 组成部分 | 应包含的内容 |
|---------|-------------|
| IS、利润表 | 利润表 |
| BS、资产负债表 | 资产负债表 |
| CF、CFS、现金流量表 | 现金流量表 |
| WC、营运资金 | 营运资金明细表 |
| DA、D&A、折旧摊销、PP&E | 折旧与摊销明细表 |
| Debt、债务 | 债务明细表 |
| NOL、税务、DTA | 净营业亏损明细表 |
| Assumptions、假设、驱动项 | 假设驱动项和输入 |
| Checks、审计、验证 | 错误检查面板 |

**结构审阅清单**
- 确认模型中有哪些组成部分（并非所有模型都包含每个明细表）
- 注意上述列表之外的模型特有部分
- 理解各部分间的依赖关系（例如哪些明细表向主报表提供数据）
- 定位每个部分的输入数据和计算输出

### 理解行列结构

**识别行结构**
- 定位每个部分的标题
- 识别章节标题及其视觉分隔
- 找到单位标注（"百万"、"%"、"倍"等）
- 注意列标题区分实际值(A)与预测值(E)期间
- 确认期间标签（如 FY2024A、FY2025E）
- 识别输入数据和计算输出

**识别列结构**
- 确认最左列为行项目标签
- 确认历史年度在预测年度之前
- 注意历史期间和预测期间之间的视觉分隔
- 检查所有部分列顺序是否一致

### 预测期间

- 通常从最近历史年度向前预测5年
- 确认历史(A)与预测(E)列有明确区分
- 确认列使用财年标记（如 FY2024A、FY2025E）

## 利润率分析

**注意：仅在用户明确要求或模型明确需要时执行以下利润率分析。如无提示，跳过此节。**

计算并展示盈利能力利润率，追踪运营效率并支持同行比较。

### 核心利润率

| 利润率 | 公式 | 衡量内容 |
|-------|------|---------|
| 毛利率 | 毛利润 / 营业收入 | 定价能力、生产效率 |
| EBITDA利润率 | EBITDA / 营业收入 | 核心营业盈利能力 |
| EBIT利润率 | EBIT / 营业收入 | 扣除折旧摊销后的营业盈利能力 |
| 净利润率 | 净利润 / 营业收入 | 底线盈利能力 |

### 利润率展示

在每个利润行项目下方直接展示利润率百分比：
- 毛利率 % → 毛利润下方
- EBIT利润率 % → EBIT下方
- EBITDA利润率 % → EBITDA下方
- 净利润率 % → 净利润下方

利润率合理性检查：毛利率 > EBITDA利润率 > EBIT利润率 > 净利润率（定义上恒成立）。

## 信用指标分析

**注意：仅在用户明确要求或模型明确需要时执行以下信用指标分析。如无提示，跳过此节。**

计算并展示信用/杠杆指标，评估财务健康状况、债务容量和契约合规性。

### 核心信用指标

| 指标 | 公式 | 衡量内容 |
|------|------|---------|
| 总债务 / EBITDA | 总债务 / LTM EBITDA | 杠杆倍数 |
| 净债务 / EBITDA | (总债务 - 现金) / LTM EBITDA | 扣除现金后的杠杆 |
| 利息覆盖率 | EBITDA / 利息支出 | 债务偿付能力 |
| 债务 / 总资本 | 总债务 / (总债务 + 权益) | 资本结构 |
| 债务 / 权益 | 总债务 / 总权益 | 财务杠杆 |
| 流动比率 | 流动资产 / 流动负债 | 短期流动性 |
| 速动比率 | (流动资产 - 存货) / 流动负债 | 即时流动性 |

### 信用指标层次检查

验证上行情景显示最强信用状况：
- 杠杆指标：上行 < 基础 < 下行（越低越好）
- 覆盖率指标：上行 > 基础 > 下行（越高越好）
- 流动性指标：上行 > 基础 > 下行（越高越好）

### 契约合规追踪

如果已知债务契约条件，添加明确的合规检查，比较实际指标与契约阈值。

## 情景分析（基础 / 上行 / 下行）

| 情景 | 描述 |
|------|------|
| 基础情景 | 管理层指引或一致预期 |
| 上行情景 | 高于指引的增长、利润率扩张 |
| 下行情景 | 低于趋势的增长、利润率压缩 |

**需敏感性测试的关键驱动项**：营业收入增长率、毛利率、销管研费用占收入比、DSO/DIO/DPO、资本支出占收入比、利率、税率。

**情景审计检查**：情景切换联动所有报表、所有情景下资产负债表平衡、现金核对通过、层次关系成立（净利润/EBITDA/FCF/利润率：上行 > 基础 > 下行）。

## 构建模型——六步流程

### 第1步：分析模型结构

在输入任何数据之前，全面审阅模型以理解其架构：

**识别输入数据和计算逻辑**
- 查找区分输入和计算的标记
- 追踪数据的前后引用和依赖关系
- 理解数据流向

**映射模型数据流向**
- 识别哪些部分向其他部分提供数据（如：假设 → 利润表 → 资产负债表 → 现金流量表）
- 注意辅助明细表及其与主报表的联动关系
- 在构建前记录模型的特定行项目和结构

### 第2步：填入数据而不破坏计算逻辑

**数据录入黄金法则**

| 法则 | 说明 |
|------|------|
| 仅编辑输入数据 | 绝不覆盖已经过计算的值（除非有意替换该计算） |
| 保持引用关系 | 修改数据时注意保持与其他部分的引用关系 |
| 匹配模型单位 | 输入数据前确认模型使用千、百万还是实际值 |
| 遵守符号约定 | 遵循模型已有的符号约定（如费用为正或为负） |
| 检查循环引用 | 如模型使用迭代计算，确保已正确处理循环 |

**安全数据录入流程**
1. 识别指定用于输入的确切数据项
2. 先输入历史数据，然后验证计算是否对该期间正确
3. 输入驱动预测计算的假设值
4. 检查计算输出以确认逻辑按预期工作
5. 如必须修改计算公式，先记录原始逻辑再做更改

**处理预设计算**
- 如果公式引用尚未填入的数据，会出现临时错误，所有输入完成后应消失
- 当计算产生意外结果时，追溯引用以识别缺失或错误的输入
- 绝不在未检查所有部分依赖关系的情况下删除数据项

### 第3步：验证公式

**公式完整性检查**

| 检查类型 | 方法 |
|---------|------|
| 追溯前导引用 | 选择计算结果 → 追溯引用，验证其引用正确的输入 |
| 追溯依赖引用 | 验证关键输入是否流向预期输出 |
| 逐步评估公式 | 对复杂计算逐步检查 |
| 检查硬编码 | 预测计算应引用假设，不应包含硬编码值 |
| 用已知值测试 | 输入简单测试值验证公式产生预期结果 |
| 跨部分一致性 | 确保相同计算逻辑适用于所有预测期间 |

**常见公式问题**
- 混合绝对/相对引用导致跨期间复制时结果错误
- 引用关系断开导致错误
- 收入起步前期间除零导致错误
- 循环引用警告（利息计算可能是有意的循环）
- 预测列之间公式不一致

**验证跨部分联动**
- 确认多部分上出现的数值是通过引用而非重复输入
- 验证明细表合计与主报表对应行项目一致
- 检查所有部分期间标签对齐

### 第4步：逐表质量检查

完成每个表的构建后执行以下验证检查：

**利润表(IS)质量检查**
- 历史期间收入数字与源数据匹配
- 所有费用行项目合计等于报告总额
- 小计（毛利润、EBIT、EBT、净利润）计算正确
- 税费计算逻辑恰当（正确处理亏损）
- 预测驱动项引用假设（无硬编码）
- 期间之间的变动方向合理

**资产负债表(BS)质量检查**
- 每个期间资产 = 负债 + 权益（首要检查）
- 现金余额与现金流量表期末现金匹配
- 营运资金科目与营运资金明细表一致（如有）
- 留存收益滚存正确：前期留存收益 + 净利润 - 股利 +/- 调整 = 期末留存收益
- 债务余额与债务明细表一致（如有）
- 所有资产负债表项目使用适当符号（资产为正，多数负债为正）

**现金流量表(CF)质量检查**
- 经营活动现金流顶部净利润与利润表净利润匹配
- 非现金加回项（折旧摊销、股份报酬等）与来源明细表/报表一致
- 营运资金变动符号正确（资产增加 = 现金使用 = 负值）
- 资本支出与PP&E明细表或固定资产滚存一致
- 筹资活动与资产负债表上债务和权益科目变动一致
- 期末现金与资产负债表现金匹配
- 期初现金等于上期期末现金

**辅助明细表质量检查**
- 期初余额等于上期期末余额
- 滚存逻辑完整（期初 + 增加 - 减少 = 期末）
- 明细表合计与主报表行项目一致
- 计算中使用的假设与假设部分匹配

### 第5步：跨报表完整性检查

验证各表后，确认三报表正确联动：

| 检查项 | 公式 | 预期结果 |
|-------|------|---------|
| 资产负债表平衡 | 资产 - 负债 - 权益 | = 0 |
| 现金核对 | CF期末现金 - BS现金 | = 0 |
| 净利润联动 | IS净利润 - CF起始净利润 | = 0 |
| 留存收益 | 前期RE + NI - 股利 - BS期末RE | = 0（按需调整股份报酬/其他项目） |

### 第6步：终审

模型完成前的最终检查：
- 切换所有情景（如有），验证检查在每个情景下均通过
- 检查所有错误并解决或记录
- 确认所有输入数据已填入（检查是否有占位值）
- 验证所有部分单位一致

## 模型验证和审计

本节汇总已完成模型的所有验证检查和审计程序。

### 核心勾稽关系（必须始终成立）

| 检查项 | 公式 | 预期结果 |
|-------|------|---------|
| 资产负债表平衡 | 资产 - 负债 - 权益 | = 0 |
| 现金核对 | CF期末现金 - BS现金 | = 0 |
| 月度与年度现金一致性 | 月度期末现金 - 年度期末现金 | = 0 |
| 净利润联动 | IS净利润 - CF起始净利润 | = 0 |
| 留存收益 | 前期RE + NI + 股份报酬 - 股利 - BS期末RE | = 0 |
| 权益筹资 | 普通股/资本溢价变动(BS) - 权益发行(CFF) | = 0 |
| 第0年权益 | 第0年筹集权益 - 第1年期初权益资本 | = 0 |

### 符号约定参考

| 报表 | 项目 | 符号约定 |
|------|------|---------|
| 经营活动现金流 | 折旧摊销、股份报酬 | 正值（加回项） |
| 经营活动现金流 | 应收账款变动（增加） | 负值（现金使用） |
| 经营活动现金流 | 应付账款变动（增加） | 正值（现金来源） |
| 投资活动现金流 | 资本支出 | 负值 |
| 筹资活动现金流 | 债务发行 | 正值 |
| 筹资活动现金流 | 债务偿还 | 负值 |
| 筹资活动现金流 | 股利支付 | 负值 |

### 循环引用处理

利息支出会产生循环：利息 → 净利润 → 现金 → 债务余额 → 利息

处理方法：启用迭代计算，设置最大迭代次数100、最大变化0.001。在假设部分添加断路器开关。

### 检查类别（9类）

**第1类：货币一致性**
- 货币已在假设中识别并记录
- 所有部分使用一致的货币符号和单位
- 单位标注与模型货币匹配

**第2类：资产负债表完整性**
- 资产 = 负债 + 权益（每个期间）
- 公式：资产 - 负债 - 权益（必须 = 0）

**第3类：现金流量完整性**
- 现金与BS一致（CF期末现金 = BS现金）
- 月度与年度现金：月度期末现金 = 年度期末现金
- 净利润与IS一致（CF净利润 = IS净利润）
- 折旧摊销与明细表一致
- 股份报酬与IS一致
- 应收账款变动、存货变动、应付账款变动与WC明细表一致
- 资本支出与DA明细表一致

**第4类：留存收益**
- 留存收益滚存检查：前期RE + NI + 股份报酬 - 股利 = 期末RE
- 展示组成部分明细以便调试

**第5类：营运资金**
- 应收账款、存货、应付账款与BS一致
- DSO、DIO、DPO合理性检查（超出正常范围时标记）

**第6类：债务明细表**
- 总债务与BS一致（流动债务 + 长期债务）
- 利息计算与IS一致

**第6b类：权益筹资**
- 权益发行所得与BS普通股/资本溢价增加一致
- 权益带来的现金增加 = 权益科目增加（必须平衡）
- 权益筹集核对：普通股/资本溢价变动(BS) = 权益发行(CFF)（必须 = 0）
- 第0年权益核对：第0年筹集权益 = 第1年期初权益资本

**第6c类：NOL净营业亏损明细表**
- 第1年/成立时NOL期初 = 0（新业务从零NOL开始）
- NOL仅在EBT < 0时增加（亏损必须实际发生才能产生NOL）
- DTA与BS一致（NOL明细表DTA = BS递延税资产）
- NOL利用额 <= EBT的80%（2017年后联邦限制）
- NOL余额非负（不能利用超过可用量）
- NOL仅在EBT < 0时产生
- 应税收入 <= 0时税费 = 0

**第7类：情景层次**
- 绝对指标：上行 > 基础 > 下行（净利润、EBITDA、FCF）
- 利润率：上行 > 基础 > 下行（毛利率%、EBITDA利润率%、净利润率%）
- 信用指标：杠杆类指标上行 < 基础 < 下行（方向反转）

**第8类：公式完整性**
- COGS、销管研费用、股份报酬由收入占比驱动（无硬编码）
- 预测年度间公式一致
- 无计算错误

**第9类：信用指标阈值**
- 根据契约阈值将指标标记为绿色/黄色/红色
- 汇总所有红色标记

### 总体检查汇总

将所有类别状态汇总为单一总体检查：
- 如所有类别通过 → "所有检查通过"
- 如任一类别失败 → "发现错误——请审阅以下内容"

### 快速调试工作流

当总体状态显示错误时：
1. 找到标记为失败的类别
2. 识别有失败的检查类别
3. 导航到源部分进行调查
4. 修复根本问题
5. 返回检查部分验证是否解决
